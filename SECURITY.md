# Безопасность

Приложение управляет физическим прибором и рассчитано на доверенную домашнюю
сеть. Аутентификации пользователей нет. Не публикуйте порт панели в интернете
и не используйте её в сети с недоверенными клиентами. Для удалённого доступа
нужен отдельно настроенный VPN или шлюз с аутентификацией и TLS.

API и PostgreSQL в штатном Compose не публикуют порты. Web доступен на порту
8080 хоста, включая LAN. Для доступа только с хоста замените привязку порта
на `127.0.0.1:8080:80`. CORS не включён; это не заменяет контроль доступа.
Изменяющие запросы с чужим Origin или Sec-Fetch-Site: cross-site отклоняются
до выполнения операции. Клиенты без браузерных заголовков могут обращаться
к API из доверенной сети; защита Origin не является аутентификацией.

Храните токен прибора в `device.local.json`, пароль БД и Telegram-реквизиты —
в `.env`. Эти файлы исключены из Git; ограничьте их доступ средствами ОС.
Не прикладывайте их, сетевые пакеты и сырые debug-логи к issue.

Проверки возможностей прибора временно меняют его состояние и требуют
наблюдения владельца. При незавершённом восстановлении новые команды
блокируются. Не повторяйте запись с неизвестным результатом автоматически.
Запускайте только один API-процесс для одного прибора и базы.

При обнаружении утечки сначала отзовите или замените секрет: удаления файла
из последнего коммита недостаточно. При сообщении об уязвимости описывайте
версию, условия воспроизведения и последствия без действующих секретов.

Аудиты зависимостей проверяют известные уязвимости, а не доказывают отсутствие
ошибок. Git-зависимость python-miio требует отдельного просмотра исходников.
