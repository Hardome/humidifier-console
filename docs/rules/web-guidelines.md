# Разработка фронта

Правила адаптированы из stageby; примеры и пути относятся к этому проекту.

## Архитектура

Стек: React/Vite, TanStack Router/Query, Kubb, React Hook Form и Zod.
При рефакторинге сохраняйте маршруты и HTTP-контракт приложения.

- `app` запускает приложение, связывает провайдеры, layout и маршруты.
- `pages` собирает экраны и связывает фильтры с URL.
- `widgets` содержит крупные повторно используемые блоки.
- `features` реализует действия пользователя. Связанные сценарии группируйте
  по области: `features/<область>/<действие>`; группа не содержит общего API.
- `entities` хранит повторно используемые предметные данные; `shared` не знает
  о предметной области. Не создавайте слои и каталоги без необходимости.
- `generated` — исключение для результата Kubb; вручную его не редактируйте.

Импорты идут только в нижележащие слои. Открывайте срез через `index.ts`;
внешний код не импортирует внутренние файлы. Используйте алиасы `@pages`,
`@widgets`, `@features`, `@entities`, `@shared`, `@api`, `@tests`.
Внутри среза используйте относительные импорты не глубже `../../`.
Сегменты: `ui` для компонентов, `model` для общих данных и типов, `lib` для
хуков и преобразований, `api` для ручной интеграции сверх генератора.

Каждый компонент имеет отдельный файл. Исключение — связанные семейства
примитивов `shared/ui`. Имена файлов — kebab-case, компонентов и типов —
PascalCase. Ориентир — 150 строк, предел — 200; исключение для семейств
UI-примитивов. Не уплотняйте разметку ради лимита.

## Данные и формы

Используйте контрактные типы, клиент и схемы из `@api`. Серверное состояние
остаётся в TanStack Query, формы — в React Hook Form. Производные значения
вычисляйте без копирования ответа в локальное состояние. После мутации
согласуйте кэш с сервером. Команду считайте выполненной только после ответа
прибора; неизвестный результат не означает успех.

Параметры списков храните в URL и проверяйте до запроса. Смена фильтров
сбрасывает offset, перелистывание сохраняет фильтры. Преобразование URL в API
выполняйте в одном месте. Не отправляйте некорректные даты и диапазоны.

Первую загрузку, обновление, пустой результат и ошибку показывайте отдельно.
Фоновый опрос не размонтирует форму и не сбрасывает ввод. Предыдущие данные
при смене фильтров сохраняйте локально через keepPreviousData; для разных ID
сущности не подставляйте чужой результат. Ошибка и повтор остаются доступны.

Схемы форм стройте на контрактных схемах. Связывайте подпись, поле и текст
ошибки через id/htmlFor и aria-describedby; используйте aria-invalid.
Во время отправки блокируйте повторное действие, после ошибки сохраняйте
ввод. Черновики добавляйте только при подтверждённой потребности.

## Стиль и проверка

Два пробела, LF, одинарные кавычки TS/JS, точки с запятой. Импорты находятся
в начале файла. Сложные пропсы описывайте локальным именованным интерфейсом.
Разделяйте настройку, вычисления, эффекты и обработчики пустыми строками.
Комментарии пишите по-русски и только для неочевидных причин и ограничений.

Перед изменением сравнивайте соседние реализации, соблюдая действующие
правила. Перед завершением проверяйте читаемость diff, границы срезов,
отдельные файлы компонентов и размеры. Не ослабляйте линтеры ради зелёного
результата; точечное исключение требует объяснения действительной причины.

Проверки описаны в [руководстве](../guides/checks.md), оформление — в
[принципах интерфейса](ui-principles.md). Backend остаётся на Python:
правила авторизации и предметной модели stageby сюда не переносятся.
