# Python: архитектура и разработка

Проект использует Python 3.12. Зависимости описаны в корневом `pyproject.toml`,
разрешённые версии — в `uv.lock`. `python-miio` закреплён на конкретном Git commit.

## Установка и команды

Установите uv, Node.js 24 и pnpm 11. Из корня проекта:

```sh
uv sync --locked
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

`corepack pnpm bootstrap` объединяет первые две команды и устанавливает Lefthook. Файл `.env` загружается
командой `pnpm dev`; при прямом запуске uvicorn передайте окружение самостоятельно
или используйте `uv run --env-file .env uvicorn api.app.main:app --workers 1`.

```sh
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked pytest --cov --cov-report=json:.tmp/coverage.json
uv run --locked python -m scripts.check_coverage
corepack pnpm check
corepack pnpm codegen
corepack pnpm test:e2e
corepack pnpm exec lefthook install
```

`pnpm check` выполняет проверки контракта, Ruff, mypy, Python-тесты с покрытием,
проверку ветвей бизнес-логики, проверки и сборку фронтенда. Порог покрытия ветвей
бизнес-логики — 85%; он считается отдельно от HTTP и LAN-адаптеров.

Для проверки миграций используйте отдельную тестовую БД:

```sh
uv run --locked alembic upgrade head
uv run --locked alembic check
```

`TEST_DATABASE_URL` включает PostgreSQL-тесты с отдельной схемой для каждого теста.
Без этой переменной тесты используют изолированную SQLite в памяти. Реальное
устройство и Telegram для тестов не нужны. Для E2E сначала установите браузер:
`corepack pnpm --dir web exec playwright install chromium`.

## Обязанности модулей

- `main.py` собирает приложение, lifespan и маршруты. Чтение конфигурации
  физического устройства начинается только при запуске lifespan.
- `routes/` — HTTP-адаптеры: DTO, параметры, статусы и operation ID.
- `service.py` координирует опрос, команды и проверку устройства под общим lock.
- `command_store.py`, `capabilities.py`, `rule_store.py`, `settings_store.py`
  содержат транзакции; `history_queries.py` — запросы истории и событий.
- `measurements.py` агрегирует показания; `events.py` фиксирует события и переходы
  тревог; `notifications.py` хранит intent доставки и обращается к Telegram.
- `scheduler.py` принимает решения без ввода-вывода.
- `device.py` изолирует LAN и стороннюю библиотеку; `device_config.py` используется
  API и CLI. `diagnose.py` остаётся совместимой точкой входа диагностики.
- `types.py` задаёт интерфейс устройства и динамические JSON-объекты. Входной
  JSON проверяется сгенерированными Pydantic DTO; ORM-данные имеют JSON-типизацию.

## Правила изменений

Сначала изменяйте исходный OpenAPI-контракт, затем запускайте codegen.
Генерируемые файлы и старые миграции вручную не редактируются. Для изменения схемы
создаётся новая Alembic-миграция. Функциональные изменения отделяйте от обновления
версий зависимостей.

Синхронные транзакции из async-сценариев выполняются через `asyncio.to_thread`.
Сессия создаётся, используется и закрывается внутри рабочего потока; между
потоками передаются значения или отсоединённые загруженные записи, а не сессии.
При добавлении транзакции не держите её открытой во время сетевого ожидания.

Потерянный ответ на запись устройства не означает, что запись не произошла.
Повторять можно чтение; неоднозначные записи и Telegram-доставки автоматически
не повторяются. Проверка capability сначала сохраняет intent восстановления.
Не увеличивайте число uvicorn workers: состояние и координация устройства
находятся в одном процессе.

Mypy работает в strict для приложения и CLI. Тела тестов тоже проверяются,
но аннотации каждой фикстуры не обязательны. Исключения для неполных аннотаций
miio ограничены LAN/CLI-адаптерами. Ruff контролирует сложность функций (12),
импорты, подозрительные конструкции, async и часть ошибок безопасности.
Локальные исключения сопровождайте причиной; глобально проверки не отключайте.

Ошибки и фоновые задачи логируются без содержимого исключений, протокольных
пакетов, паролей и токенов. Не включайте сырые debug-логи miio/httpx.

## Аудит зависимостей

CI экспортирует runtime- и dev-зависимости из lock-файла и проверяет их pip-audit.
Git-зависимость `python-miio` аудитор пропускает: успешный аудит не является
проверкой её исходников. Её commit обновляется отдельно после проверки адаптера.
Не добавляйте общие исключения уязвимостей; адресное исключение требует причины
и даты пересмотра.

## Результаты проверок

В итогах задачи указывайте выполненные проверки и непроверенные сценарии.
Проверка LAN требует реального устройства;
автоматические тесты используют внедрённую подмену и не обращаются к прибору.
