# Разработка с AI

AI помогает исследовать код и готовить изменения; ответственность за принятое
решение и результат проверки остаётся у автора. Наличие AGENTS.md само по себе
не подтверждает качество реализации.

1. Сформулируйте наблюдаемую проблему и критерий приёмки. Прочитайте карту
   документации и правила затрагиваемой области.
2. Проверьте текущее поведение и состояние Git. Не перезаписывайте чужие
   изменения; не передавайте агенту секреты и протокольные дампы.
3. Подготовьте минимальное исправление. Контракт меняйте в исходном YAML,
   модели и клиент получайте через codegen.
4. Для ошибки поведения добавьте регрессионный тест, который различает
   исправленное и прежнее поведение. Проверьте diff вручную.
5. Запустите проверки из руководства. Отдельно укажите, что не проверялось;
   симуляция не подтверждает поведение физического устройства.

## Пример: повторное выполнение команды

В рамках подготовки портфолио обнаружено, что захват команды переводил её
в running независимо от исходного статуса. Повторный вызов исполнителя мог
снова записать значение в прибор.

Критерий приёмки: несколько вызовов исполнения одного идентификатора приводят
ровно к одной записи в устройство. Решение — атомарный переход pending → running
в CommandStore. Регрессионный тест
`test_duplicate_execution_does_not_repeat_device_write` запускает два вызова
параллельно и один после завершения, проверяя число записей и итоговый статус.
Тест использует подмену прибора и выполняется также на PostgreSQL.
