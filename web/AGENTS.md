# Правила фронта

Читайте [правила разработки](../docs/rules/web-guidelines.md) при изменении
фронта и [принципы UI](../docs/rules/ui-principles.md) при изменении оформления.
Проверки: `corepack pnpm --dir web check`; браузер: `corepack pnpm test:e2e`.
Сохраняйте публичные API срезов, существующие маршруты и контракт сервера.
Не переносите палитру, размеры или предметную модель stageby.

Разделяйте логические блоки пустыми строками: настройку формы, запросы,
вычисления, эффекты и обработчики. Перед return оставляйте пустую строку.
В тестах отделяйте подготовку, действие и проверку результата.
Форматирование не должно уплотнять код ради ограничения числа строк.
Исходники и исполняемые конфигурации пишите на TypeScript.

Именованные наборы значений описывайте объектами `const ... as const`, без
объявлений `enum`. Коды прибора и бизнес-ограничения храните в моделях и
используйте по именам в компонентах и тестах. Строковые значения API берите
из сгенерированных констант. Для классов используйте пакет `cn` напрямую,
для вариантов компонентов — `tv` из `tailwind-variants`.

В callbacks используйте предметные имена: `capability`, `action`, `point`,
`query`, `selectedValues`. Не сокращайте их до одной буквы; во вложенных
обработчиках различайте текущий элемент и кандидата на выбор.
